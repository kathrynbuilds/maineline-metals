# Operations log — Genesis Carrier Capacity System

## 2026-07-09 — Phase 1: Census refresh pipeline

Bootstrapped the repo (zero-dependency Node 22, ESM) and shipped `npm run refresh-census`: it pulls the FMCSA Company Census (dataset az4n-8mr2) via the Socrata SODA API with server-side state/power-unit filters — falling back automatically to a simpler query if the API rejects the numeric cast, or to a downloaded CSV via `--csv <path>` and the new streaming `filter-carrier-census.js` — then filters to AR/TN/MS/GA/AL, 5–50 power units, interstate, metal sheets/coils/rolls cargo, MCS-150 within 24 months, and upserts into the Airtable Carriers table keyed on DOT Number. New carriers enter at Status = Researched, Source = FMCSA Census, with the Lane Batch from `--batch` (default `Blytheville-Atlanta (origin)`); existing records get blank fields filled only, with any conflicting values appended to Notes (never overwritten) and Status/Source/Lane Batch left strictly alone. Flags: `--dry-run` (reads but writes nothing), `--batch`, `--states`, `--limit`, `--csv`. Column names are auto-detected against both legacy MCMIS and MOTUS-era schemas and the chosen mapping is printed on every run. Requires `AIRTABLE_PAT` in `.env`. Verified by 19 passing tests covering the double-run-zero-new acceptance check, dry-run writing nothing, 10-record write batching, and blank-fill/conflict-note behavior. Note: this sandbox's proxy blocks data.transportation.gov, so the live SODA call was validated against mocked responses — first real run should be `npm run refresh-census -- --dry-run --limit 25`.
