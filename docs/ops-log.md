# Operations log — Genesis Carrier Capacity System

## 2026-07-09 — Phase 1: Census refresh pipeline

Bootstrapped the repo (zero-dependency Node 22, ESM) and shipped `npm run refresh-census`: it pulls the FMCSA Company Census (dataset az4n-8mr2) via the Socrata SODA API with server-side state/power-unit filters — falling back automatically to a simpler query if the API rejects the numeric cast, or to a downloaded CSV via `--csv <path>` and the new streaming `filter-carrier-census.js` — then filters to AR/TN/MS/GA/AL, 5–50 power units, interstate, metal sheets/coils/rolls cargo, MCS-150 within 24 months, and upserts into the Airtable Carriers table keyed on DOT Number. New carriers enter at Status = Researched, Source = FMCSA Census, with the Lane Batch from `--batch` (default `Blytheville-Atlanta (origin)`); existing records get blank fields filled only, with any conflicting values appended to Notes (never overwritten) and Status/Source/Lane Batch left strictly alone. Flags: `--dry-run` (reads but writes nothing), `--batch`, `--states`, `--limit`, `--csv`. Column names are auto-detected against both legacy MCMIS and MOTUS-era schemas and the chosen mapping is printed on every run. Requires `AIRTABLE_PAT` in `.env`. Verified by 19 passing tests covering the double-run-zero-new acceptance check, dry-run writing nothing, 10-record write batching, and blank-fill/conflict-note behavior. Note: this sandbox's proxy blocks data.transportation.gov, so the live SODA call was validated against mocked responses — first real run should be `npm run refresh-census -- --dry-run --limit 25`.

## 2026-07-09 — Phase 2: Authority verification

Shipped `npm run verify-carriers`: every carrier with Status Researched through Active is checked against the FMCSA QCMobile API (`FMCSA_WEBKEY` in `.env`) and gets Authority Status (Active/Inactive/Not Found/Error), Authority Verified Date, and OOS Flag written back. Inactive-authority or out-of-service carriers are demoted to Do Not Use with a timestamped explanation appended to Notes — the only automated status change in the system, and strictly downward; "Not Found" DOTs are flagged in Notes as a possible fraud signal but left for a human, and API errors touch nothing. Responses are cached in `.cache/authority.json` and anything verified within 30 days is skipped unless `--force`; requests are throttled at ~2/sec. The three authority fields could not be created from this sandbox (Airtable connector write approval unavailable), so the script resolves them **by name** via the Meta API at runtime and `npm run verify-carriers -- --provision` creates them on first run (PAT needs `schema.bases:write`) — exact names: "Authority Status", "Authority Verified Date", "OOS Flag". Verified by 11 new tests: revoked→Do Not Use+note, OOS→demote+flag, active→date refresh with status untouched, 30-day skip/--force, cache dedupe, not-found/no-demote, dry-run-writes-nothing, and field provisioning.

## 2026-07-09 — Phase 3: TMS core, dispatch gate, packet assembler

Shipped the minimal TMS and wired invariant 1 into it: `tms/loads.js` keeps a forward-only load lifecycle (Booked → Dispatched → In Transit → Delivered → Invoiced → Paid) in `data/loads.json`, and `node tms/rate-confirmation.js <loadId>` fetches the carrier live from Airtable (read-through, Airtable stays canonical) and runs `carriers/dispatch-gate.js` before rendering anything — generation hard-fails with the complete punch list unless Status ∈ {Packet Complete, Active}, Coil Exclusion Status = "Confirmed No Exclusion", W-9/COI/BCA all on file, and authority verification ≤ 30 days old, with OOS/non-Active authority as an extra block. `carriers/packet-assembler.js <DOT>` drafts whichever packet emails are missing (W-9 request, BCA cover, producer-direct COI request that explicitly asks for written coil-exclusion confirmation) through `carriers/approval-queue.js`, which writes an `outbox/` file plus an Airtable Activity (Type Email, Email Status Draft, Logged By System, linked to the carrier) — the system contains no send path at all. `npm run dashboard` serves pipeline counts and loads at localhost:8642. 18 new tests (48 total) prove each of the six gate failure modes blocks independently with a distinct message, all failures report together, a stale verification from Phase 2 blocks Phase 3, and the COI request never goes to the carrier's own email.

## 2026-07-09 — Phase 4: Carrier email intake loop

Shipped the intake loop: raw carrier replies land in `inbox-drop/` from either adapter — a hand-rolled IMAP4rev1 poller (`carriers/email-intake/imap-poller.js`, UNSEEN → .eml) or a token-authenticated webhook receiver (`webhook-receiver.js`, verified live: 401 without the token, 202 + drop file with it) — and `npm run intake` parses each message (minimal MIME parser handling multipart, quoted-printable, base64, RFC 2047), matches it to a carrier by sender email then DOT/MC in the body (unmatched mail quarantines to `inbox-drop/unmatched/`), and calls the Claude Messages API with a forced tool schema to classify the reply and extract the twelve intake answers. Updates are blank-fill-only with conflicts logged to Notes, Contacted→Responded fires only on a real (non-out-of-office) reply, every message is logged as an Activity with the raw body, Responded+ carriers still at "Not Verified" coil exclusion get an urgent producer-confirmation Task, and a factoring-company mismatch opens an urgent fraud-review Task. `npm run followups` (run daily) drafts day-3/day-8 bumps for silent Contacted carriers, declines them at day 15 with a Notes explanation, and sends a day-2 packet reminder listing exactly what's missing — all drafts to `outbox/` + Airtable Draft Activities only; the repo contains no send path. 23 new tests (71 total) cover the five acceptance reply fixtures end-to-end, task dedupe, unmatched quarantine, no-promotion-past-Responded, cadence windows, draft dedupe across runs, and the Claude request shape. Requires `ANTHROPIC_API_KEY` (plus IMAP_* or INTAKE_WEBHOOK_TOKEN) in `.env`.
